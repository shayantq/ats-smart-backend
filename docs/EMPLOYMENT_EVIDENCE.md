# اصلاح سوابق مستند رزومه — فقط لوکال

علت اصلی، استفاده از پیش‌بینی مدل به‌عنوان سابقه، اولویت‌دادن رابط به ردیف‌های failed و تشخیص ناقص تاریخ/مرز پروژه‌ها بود. ترتیب قطعه‌های فارسی در PDF نیز با ترتیب دیداری فرق داشت.

## تغییرات

- `app/core/employment_evidence.py`: تشخیص بخش سوابق، توقف در مرز پروژه‌ها/تحصیلات، نرمال‌سازی ارقام و حروف، اتصال عنوان و شرکت دارای شاهد، حذف تکرار و تحلیل تاریخ. شاهد اصلی و provenance در دادهٔ رمز‌شدهٔ قبلی نگه داشته می‌شود.
- `app/core/resume_parser.py` و اسکیماهای پارس/عامل: سوابق مستند با `source=resume_evidence_v2` و `evidence` مشخص می‌شوند. fallback قدیمی برای سازگاری پارسر باقی است، ولی در مسیر مدل منبع سابقهٔ معتبر نیست.
- `app/model_inference/pipeline.py`: سابقه و مدت ادعایی مدل وارد تاریخچهٔ واقعی نمی‌شوند. سوابق از متن اصلی استخراج و اعتبارسنجی می‌شوند. هشدار کیفیت پیش‌بینی همچنان باقی است.
- `app/tasks/resume_model.py`: cache پارس نسخهٔ ۲ دارد؛ متن معتبر همان فایل دوباره استفاده می‌شود ولی پارس قدیمی و تحلیل قبلی مانع بازارزیابی نیستند. قفل تلاش، retry و وضعیت استخدام حفظ شدند.
- `frontend/src/components/dossierData.ts`: ردیف failed مدل و fallback بدون شاهد حذف می‌شوند. تنها سابقهٔ دارای provenance و شاهد از مسیر معتبر نمایش داده می‌شود.
- با تأیید کاربر `jdatetime==5.2.0` و `jalali-core==1.0.0` اضافه شدند. API و Worker محلی از تصویر `ats-editorial-api:employment` استفاده می‌کنند. ساخت آن از تصویر موجود، کاربر غیرریشه را حفظ می‌کند؛ تغییر ساختار دیتابیس لازم نبود.

تبدیل تقویم با کتابخانه انجام می‌شود، نه اختلاف ثابت ۶۲۱ سال. تاریخ ماهانه/سالانه یک بازهٔ عدم قطعیت دارد؛ روزی به آن نسبت داده نمی‌شود. برای جمع سابقه، حداقل مدت قابل‌اثبات میان این بازه‌ها محاسبه و بازه‌های هم‌پوشان در تقویم مشترک ادغام می‌شوند. این عدد پایین‌کران است، نه مدت دقیق روزانه. تاریخ نامشخص، معکوس، آینده یا دورهٔ بیش از ۴۰ سال وارد جمع نمی‌شود. تاریخ مرجع در تابع تحلیل قابل تزریق است و تست‌ها تاریخ ثابت دارند.

## نتیجهٔ واقعی

جدیدترین درخواست محلی منطبق با SHA256 فایل معرفی‌شده، پس از اطمینان از خالی‌بودن صف و داشتن یک Worker، دقیقاً یک بار دوباره صف‌گیری شد. رکوردهای دیگر bulk-update نشدند.

نتیجهٔ ذخیره‌شده و نمای واقعی پرونده در Edge بررسی شدند:

- دقیقاً یک سابقه: «کارآموز توسعه بکاند — ATS Smart».
- بازهٔ نمایشی: «تیر ۱۴۰۵ تا اکنون»؛ تاریخ معتبر است.
- LogiTrack در تاریخچهٔ استخدام وارد نشده؛ دو سابقهٔ پیش‌بینی‌شدهٔ تکراری و ادعای ۱۰ سال در تاریخچهٔ این درخواست وجود ندارند.
- متن خام از cache استفاده شد و پارس قبلی استفاده نشد؛ وضعیت استخدام Draft حفظ شد.
- در مرورگر، بخش سوابق فقط یک ردیف ATS Smart داشت؛ screenshot یا متن رزومه ذخیره نشد.

شواهد عددی/غیرهویتی در مسیر ignored `training/reports/resume-repair/`:
`employment-result.json`، `employment-browser-result.json` و `employment-frontend.log`.
شناسهٔ درخواست منتخب فقط در `employment-target.json` محلی نگه داشته شده است.

## بررسی‌ها

```powershell
.\.venv\Scripts\python.exe -m pytest tests/unit/test_employment_evidence.py tests/unit/test_resume_parser.py tests/unit/test_resume_model.py tests/unit/test_model_inference.py tests/unit/test_agents_skill_experience.py tests/unit/test_queue_retry.py -q
cd frontend
npm run build
npm test -- --runInBand
```

اجرای مرتبط بک‌اند: ۹۹ تست پاس. build فرانت‌اند موفق و ۵۳ تست در ۱۳ suite پاس شدند. Black و Flake8 فایل‌های مربوط بررسی شدند. تست‌ها شامل ارقام فارسی/عربی، ماه شمسی، بازهٔ عددی، RTL، تاریخ مرجع ثابت، تاریخ معکوس/آینده/نامعتبر، تکرار، دو نقش متفاوت در یک شرکت، هم‌پوشانی با تقویم متفاوت، عدم ساخت روز مجهول و رد دو سابقهٔ ساختگی مدل هستند. تست رابط، fallback نامستند را نیز پوشش می‌دهد.

برای راه‌اندازی پس از خاموشی، از ریشه:

```powershell
docker build -f dev/Dockerfile.resume-local -t ats-editorial-api:employment .
node dev/resume-local.cjs up
```

در `http://localhost:5173` صفحه را تازه کنید و جدیدترین درخواست مربوط به این فایل را باز کنید. در بخش سوابق باید فقط سابقه و تاریخ بالا دیده شود. API روی `http://localhost:8000/api/v1` است.

## حدود اعتبار

استخراج عمداً محافظه‌کارانه است؛ چیدمان‌ها، عنوان‌ها یا تاریخ‌های ناشناخته به اطلاعات نامعلوم منتهی می‌شوند، نه حدس مدل. پوشش تمام قالب‌های رزومه ادعا نمی‌شود. داده‌های قدیمی فاقد provenance ممکن است تا بازارزیابی در UI سابقه نشان ندهند؛ رکوردهای دیگر بدون اجازه بازنویسی نشدند. امتیاز و سایر پیش‌بینی‌های مدل همچنان نیازمند ارزیابی کیفیت جداگانه‌اند. این بررسی اثبات کیفیت کلی مدل آموزش‌دیده با دادهٔ ساختگی نیست. به سرور وصل نشدیم؛ commit، push و deploy انجام نشده است.
