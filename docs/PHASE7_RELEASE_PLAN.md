# برنامهٔ انتشار و بازگشت — اجرا نشده

این سند فقط برنامه است. هیچ commit، push، اتصال سرور یا rollout در فاز ۷ انجام نشد. دروازهٔ کیفیت فعلی باز است: نتایج ساختگی PDF/OCR به اهداف پیشنهادی نمی‌رسند و دادهٔ بازبینی‌شدهٔ مستقل HR نداریم.

## پیش از تصمیم انتشار

۱. گزارش `PHASE7_IMPLEMENTATION.md` و شکست‌های ارزیابی بررسی شوند؛ کیفیت تکنیکی، صحت داده و سودمندی HR سه معیار جدا هستند. نتایج آزمون نام/جنسیت گواهی انصاف نیستند. برای پایلوت محدود با بازبینی اجباری انسانی نیز تصمیم جداگانه لازم است.

۲. تغییرات فازهای قبل و کارهای نامرتبط در Git جدا بازبینی شوند. وزن، دیتاست، artifact، credential و PDF واقعی وارد commit نشوند. فایل‌های ignored گزارش فقط در صورت انتخاب آگاهانه و پس از بررسی قابل اشتراک‌اند.

۳. backup معتبر دیتابیس، نسخهٔ کلیدهای رمزنگاری و امکان restore بررسی شوند. migrationها برای DB اجراشده بازنویسی نشوند. این فاز schema جدید ندارد؛ چهار جدول فاز ۶ و ستون وضعیت فاز قبلی هنوز باید در محیط مقصد migrate شوند.

۴. وضعیت ذخیره‌سازی مقصد مشخص شود. برای local، دریافت عمومی `/media` بسته و مسیر `GET /api/v1/resumes/{id}/file` با Bearer token جایگزین است. لینک خام قدیمی دیگر مسیر دریافت عمومی نیست؛ مصرف‌کنندگان بیرونی باید به API احرازشده مهاجرت کنند. فرانت‌اند فعلی از پیش‌نمایش امن استفاده می‌کند؛ Worker از volume مشترک می‌خواند.

۵. برای S3، خصوصی‌بودن bucket و سیاست دسترسی باید جداگانه تأیید شود؛ تغییر bucket در این کار انجام نشده است. دریافت خصوصی S3 در endpoint تازه فعلاً ۵۰۱ می‌دهد و نباید با لینک عمومی به‌عنوان راه‌حل امنیتی جایگزین شود. محیط S3 بدون طراحی/تأیید این مسیر آمادهٔ انتشار این قابلیت نیست.

۶. سیاست نگه‌داری نسخه‌ها با مالک داده مشخص شود. ابزار `dev/dossier-retention-preview.py --older-than-days 90 --keep-latest 2` فقط مثال dry-run است؛ حذف دوره‌ای یا DELETE واقعی ندارد. نگه‌داری بلندمدت دادهٔ شخصی را با انتخاب پیش‌فرض و بی‌اجازه فعال نکنید.

## انتشار مرحله‌ای پس از مجوز جداگانه

۱. پنجرهٔ مهاجرت با backup و کنترل lock timeout؛ ابتدا migrationهای افزایشی اجرا شوند، سپس API/Worker جدید و پس از health صحیح، فرانت‌اند. اجرای کامل upgrade/downgrade/upgrade در دیتابیس موقت آزموده شد؛ این شاهد، مجوز downgrade پایگاه واقعی نیست.

۲. آرگومان RQ همان application_id و file_url باقی است؛ امضا یا نام تابع صف تغییر نکرده. Parser نسخهٔ ۶ در پردازش بعدی اعمال می‌شود؛ بازتحلیل تمام رزومه‌ها خودکار فعال نشود. گروه‌های قدیمی بدون claim پایدار با حدس دوباره enqueue نشوند.

۳. health/readiness، تعداد کارهای فعال/منتظر، خطای model/queue، ۴۰۱/۴۰۴ فایل و no-store بررسی شوند. یک fixture ساختگی اختصاصی در مقصد و سپس پاک‌سازی همان fixture؛ پروندهٔ واقعی بدون دستور دوباره صف‌گیری نشود. لاگ‌ها شامل متن رزومه، یادداشت یا کلید نباشند.

۴. کیفیت سند/تحلیل، حفظ اصلاح انسانی، منع دسترسی بین سازمان‌ها و دریافت فایل مجاز/نامجاز بررسی شوند. نرخ ۴۲۹ پیش‌نمایش باید از خطای ناشناخته جدا گزارش شود. برای زمان CPU/حافظهٔ سرور محدود، هدف با اندازه‌گیری همان مقصد تعیین شود؛ زمان GPU لپ‌تاپ تضمین آن نیست.

۵. رشد حافظه و صف در بازهٔ کاری طولانی بررسی شود؛ چهار نمونهٔ کوتاه VRAM اثبات نبود نشت نیستند. ممیزی انسانی صفحه‌خوان و مجموعهٔ مستقل HR همچنان لازم‌اند.

## بازگشت

- در رگرسیون عملکردی، نسخهٔ قبلی API/Worker/فرانت‌اند با روش معمول استقرار برگردد و جدول/ستون‌های افزایشی فعلاً باقی بمانند. با قدیمی‌شدن کد، دادهٔ بازبینی جدید حذف نشود.
- downgrade جدول‌های فاز ۶ تاریخچه و یادداشت‌ها را حذف می‌کند؛ روی دادهٔ واقعی مسیر پیش‌فرض rollback نیست. تنها با backup، برنامهٔ نگه‌داری و مجوز مستقل بررسی شود.
- شکست ارسال به Redis: نویسندهٔ گروه از بازیابی محدود با همان claim استفاده کند. این عملیات شکست محتوایی/مدل را خودکار retry نمی‌کند. پس از سقف سه تلاش، ابتدا وضعیت broker و job موجود بررسی شود؛ اسکریپت بی‌پایان نسازید.
- اگر Redis به‌کلی دادهٔ jobها را از دست بدهد، تضمین deduplication آن از بین می‌رود. بررسی DB، attempt/fencing و بازیابی کنترل‌شده لازم است؛ نتیجهٔ سالم با بازپخش کور جایگزین نشود.

## متن پیشنهادی جیرا

فاز ۷ محلی شامل ارزیابی ساختگی توسعه‌یافته و PDF/OCR ثابت، آزمون ثبات نام/جنسیت با صلاحیت ثابت، رفع تشخیص اشتباه مسئولیت به‌عنوان شغل، حفظ نام کامل شرکت و اصلاح provenance فیلد غایب انجام شد. ارسال گروهی دارای outbox پایدار، enqueue اتمیک و بازیابی محدود نویسنده شد؛ مسیر عمومی فایل رزومه بسته و دریافت احرازشده اضافه شد. حالت محدود بدون نمایش هویت، ابزار dry-run نگه‌داری و برنامهٔ انتشار/rollback آماده شدند. تست‌های مرتبط، build و ممیزی کیبورد/کنتراست/Lighthouse بررسی شدند؛ Lighthouse روشن و تاریک ۱۰۰ است. کیفیت عمومی هنوز تأیید نشده: ارزیابی فعلی PDF/OCR ساختگی precision حدود ۹۵٫۹٪ و recall حدود ۷۸٫۲٪ دارد و مرجع مستقل HR موجود نیست. پوش یا دیپلوی انجام نشده است.
