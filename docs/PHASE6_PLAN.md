# طرح اجرایی فاز ۶ — بازبینی و همکاری

این طرح فقط برای محیط محلی است. برای اصلاحات محافظت‌شده، یادداشت خصوصی و تاریخچهٔ قابل اعتماد، ذخیره‌کردن داده در خروجی قابل بازنویسی مدل مناسب نیست.

وضعیت اجرا: کاربر ایجاد migration و اجرای آن فقط روی دیتابیس محلی را تأیید کرد. چهار جدول ایجاد شدند و head محلی `a61d3e947b22` است. جزئیات پیاده‌سازی، آزمون‌ها و محدودیت‌ها در `PHASE6_IMPLEMENTATION.md` ثبت می‌شوند؛ متن زیر طرح اولیه و مرزهای همان تأیید است.

## تغییر ساختار پیشنهادی

چهار جدول تازه، بدون حذف یا تغییر ستون‌های فعلی:

| جدول | ستون‌های اصلی | هدف |
|---|---|---|
| `dossier_review_heads` | application_id کلید اصلی، tenant_id، revision عددی | قفل کوتاه و جلوگیری از بازنویسی تغییر همکار با نسخهٔ قدیمی |
| `dossier_review_events` | id، application_id، resume_id، tenant_id، actor_id، action، visibility، created_at، payload متن رمز‌شده | اصلاح، یادداشت خصوصی/تیمی، بازبینی بخش، shortlist و بازخورد؛ وقایع از API ویرایش یا حذف نمی‌شوند |
| `dossier_analysis_versions` | id، application_id، resume_id، tenant_id، created_at، fingerprint، payload متن رمز‌شده | عکس نسخهٔ رزومه/تحلیل/تنظیم آگهی برای مقایسهٔ مستند |
| `dossier_reanalysis_batches` | id، tenant_id، actor_id، job_id، created_at، payload متن رمز‌شده | گروه انتخاب‌شده، پیشرفت و نتیجهٔ enqueue محدود، بدون متن رزومه در Redis یا لاگ |

هر جدول فیلتر سازمان و RLS دارد. یادداشت خصوصی افزون بر فیلتر API، در سیاست SELECT دیتابیس به نویسنده محدود می‌شود. payload با `EncryptedJSON` موجود رمز می‌شود؛ متن یادداشت و اصلاح وارد log و ستون JSONB عملیاتی نمی‌شود. FK به درخواست/رزومه دارد؛ پاک‌سازی حق فراموش‌شدن باید payloadهای جدید را نیز حذف کند. هیچ دادهٔ واقعی برای پرکردن جدول‌ها backfill نمی‌شود.

## رفتار مورد انتظار

- خروجی مدل و اصلاح انسانی جدا می‌مانند. اصلاح به هش فایل و اثرانگشت رکورد منبع متصل است؛ فایل/رکورد متفاوت به‌صورت بی‌صدا اصلاح نسخهٔ قبلی را به ارث نمی‌برد.
- رویداد شامل کاربر، زمان، دلیل و شاهد است. revision قدیمی ۴۰۹ می‌گیرد. یادداشت خصوصی در پاسخ همکار دیده نمی‌شود.
- snapshot آگهی و تحلیل در اجرای موفق تازه ثبت می‌شود؛ نسخهٔ تاریخیِ موجودنیست ساخته یا حدس زده نمی‌شود.
- مقایسهٔ حداکثر ده درخواستِ یک آگهی، وضعیت شروط و دلیل تفاوت را نمایش می‌دهد؛ امتیاز با نسخه/وزن متفاوت یا تحلیل ناقص مبنای رتبه‌بندی نیست.
- تحلیل مجدد حداکثر بیست درخواست منتخب از صف resumes استفاده می‌کند؛ همان timeout و retry باقی‌اند. کارِ فعال دوباره صف‌گیری نمی‌شود. تصحیح انسانی مستقل باقی می‌ماند.
- تکمیل اطلاعات در UI پیشنهاد می‌شود؛ هیچ پیام یا ایمیل خودکار به کارجو ارسال نمی‌شود. بازخورد، دادهٔ آموزش واقعی نامیده نمی‌شود و آموزش مجددی انجام نمی‌شود.

طبق مرزهای نقشهٔ کار: «در هر فاز تغییر schema، وابستگی/دانلود جدید، انتقال داده، هزینه و اقدام مخرب نیازمند اجازه است.» ایجاد migration و اجرای آن فقط روی دیتابیس محلی پس از تأیید کاربر انجام می‌شود. تا آن زمان منطق مستقل و تست‌های بدون تغییر دیتابیس قابل پیشبردند. مرجع: `RESUME_ANALYSIS_ROADMAP.md`، بخش الزام‌های سراسری و مجوزها.
