# اکوسیستم چندعاملی پردازش رزومه (Multi-Agent)

خط لوله‌ی ترتیبی پردازش رزومه به یک **عامل ناظر (Supervisor)** و **سه عامل تخصصی موازی** تبدیل شده است. هر عامل بخشی از رزومه را تحلیل می‌کند و ناظر خروجی‌ها را به یک JSON یکپارچه و بدون تعارض ساختاری می‌رساند و نمره‌ی نهایی تطابق را می‌سازد.

| فایل | نقش |
|---|---|
| `app/agents/graph.py` | گراف LangGraph (`StateGraph`)، Fan-out/Fan-in، سقف زمانی و ایزوله‌سازی هر عامل |
| `app/agents/supervisor.py` | ناظر: توزیع (OCR و NER یک‌بار) و جمع‌بندی (قواعد حل تعارض، نمره) |
| `app/agents/skill_agent.py` | عامل ۱، استخراج مهارت و تطبیق با گراف مهارت |
| `app/agents/experience_agent.py` | عامل ۲، اعتبارسنجی سوابق کاری (تداخل، بزرگ‌نمایی) |
| `app/agents/soft_skills_agent.py` · `data/soft_skills_lexicon.json` | عامل ۳، تناسب فرهنگی و مهارت‌های نرم |
| `app/agents/text_signals.py` | سیگنال‌های متنی مشترک (ادعای «N سال»)، یک‌بار در توزیع |
| `app/agents/schema.py` | قرارداد خروجی (`agents-v1`) |
| `app/tasks/resume_processing.py` | اتصال به صف RQ «resumes»، `RESUME_PIPELINE` |

---

## ۱. گراف

```
                                     ┌──► skill_extraction ──────────┐
 صف resumes ─► فایل خام ─► supervisor_dispatch ──► experience_validation ──► supervisor_aggregate ─► UnifiedAnalysis
 (process_resume_task)     OCR + NER + سیگنال‌ها    └──► culture_fit_soft_skills ──┘    حل تعارض + نمره     │
                           (فقط یک‌بار)                    (هم‌زمان)                                           ▼
                                                                         resumes.agent_analysis (رمزشده) · skill_analysis · score_ai
```

- **ورودی:** RQ همان ورودی قبلی است: شناسه‌ی درخواست و آدرس فایل (بدون متن یا داده‌ی رزومه). صف، سیاست تلاش مجدد و تابع `process_resume_task` تغییری نکرده‌اند.
- **ناظر (توزیع):** فایل خام را می‌گیرد، متن را **یک‌بار** استخراج می‌کند (با OCR در صورت نیاز)، **یک‌بار** پارس می‌کند (NER) و سیگنال‌های مشترک را می‌سازد. همین ورودی مشترک به سه عامل داده می‌شود؛ هیچ عاملی OCR یا NER را تکرار نمی‌کند.
- **Fan-out/Fan-in:** هر سه عامل در یک Superstep شروع می‌شوند و `supervisor_aggregate` فقط بعد از تمام شدن هر سه اجرا می‌شود (`add_edge([سه عامل], aggregate)`).
- **اجرا:** هر عامل در یک Thread از Thread Pool ماندگار اجرا می‌شود، با سقف `AGENT_TIMEOUT_SECONDS` (پیش‌فرض ۲۰ ثانیه).
- **شکست یا تمام شدن زمان یک عامل:** بخش همان عامل `{"status": "failed"}` می‌شود، وضعیت کل `partial` می‌شود، و ناظر با بقیه‌ی خروجی‌ها جمع‌بندی و نمره را انجام می‌دهد. پیام خطا هرگز وارد خروجی یا لاگ نمی‌شود، چون ممکن است تکه‌ای از متن رزومه باشد؛ فقط نوع خطا ثبت می‌شود.
- **موازی بودن در عمل:** عامل‌ها کار CPU پایتونی‌اند. با GIL، «موازی» یعنی هم‌پوشانی زمانی (اثبات‌شده با زمان‌های شروع و پایان هر عامل)، نه چند برابر شدن سرعت روی چند هسته. همین معماری برای عامل‌های I/O-محور (مثلاً مدل زبانی) موازی واقعی است.
- **رم:** LangGraph فقط در Worker بارگذاری می‌شود (حدود ۵۵ مگابایت برای هر پردازه). API آن را import نمی‌کند.

## ۲. قرارداد عامل‌ها

همه‌ی مدل‌ها `extra="forbid"` دارند: کلید ناشناخته یا تغییر نوع، خطای اعتبارسنجی است. سال‌ها همیشه `float` و مهارت‌ها همیشه نام استاندارد گراف مهارت‌اند.

| عامل | خروجی |
|---|---|
| **استخراج مهارت** | برای هر مهارت: `name` (نام استاندارد)، `core`/`category` (گره والد)، `evidence_count` (ذکر مستقیم)، `inferred` (مثلاً Python از روی FastAPI)، `confidence` (۰٫۶ + ۰٫۱ برای هر تکرار؛ استنتاجی ۰٫۵)، `claimed_years`. مجموعه‌ی مهارت‌ها دقیقاً همان خط لوله‌ی قبلی است. |
| **اعتبارسنجی سوابق** | `entries` (با سال‌های یکسان‌شده‌ی شمسی/میلادی)، `total_experience_years` (خالص بعد از ادغام تداخل‌ها روی تقویم یکسان)، `overlaps` (کدام دو ردیف، چند سال)، `invalid_periods`، `flags` |
| **تناسب فرهنگی و مهارت‌های نرم** | `soft_skills` (ارتباط، رهبری، کار تیمی، مسئولیت‌پذیری، یادگیری، حل مسئله، انعطاف، مدیریت زمان؛ امتیاز ۰ تا ۱ با عبارت‌های شاهد)، `tone` (قاطع، جمعی، فردی و محتاط در هر ۱۰۰ کلمه؛ نسبت جمله‌های مجهول؛ لحن غالب)، `confidence` |

**هشدارهای بزرگ‌نمایی** (عامل سوابق؛ هر کدام با `severity` و `evidence` کوتاه برای HR):

| کد | قاعده |
|---|---|
| `claimed_years_exceed_history` | ادعای «N سال سابقه» بیش از ۲ سال بیشتر از بازه‌های معتبر (اختلاف ≥ ۵ سال = high) |
| `seniority_title_vs_tenure` | عنوان ارشد (≥ ۳ سال)، سرپرست/مدیر (≥ ۵)، مدیر ارشد/CTO (≥ ۷) با سابقه‌ی کمتر |
| `concurrent_full_time_roles` | بیش از دو شغل هم‌زمان در یک بازه |
| `skill_years_exceed_career` | «N سال مهارت X» بیش از ۲ سال بیشتر از کل سابقه |
| `invalid_period` | بازه‌ی آینده، وارونه یا نامعلوم (قواعد تحلیل‌گر قبلی) |

**واژه‌نامه:** عبارت‌ها در فایل JSON نگه داشته می‌شوند، نه در کد. تطبیق انگلیسی با مرز کلمه انجام می‌شود و تطبیق فارسی با مرز حرف فارسی («ما» داخل «ماه» شمرده نمی‌شود). هر گروه با یک الگوی ترکیبی جستجو می‌شود (عبارت بلندتر اول).

## ۳. قواعد حل تعارض (عامل ناظر)

| کد | عامل‌ها | قاعده |
|---|---|---|
| `skill_years_capped` | مهارت ↔ سوابق | ادعای سال یک مهارت بیش از سابقه‌ی تأییدشده ← سقف = سابقه‌ی تأییدشده، اطمینان × ۰٫۷ |
| `claimed_total_overridden` | سوابق | ادعای کل سابقه در متن ← سابقه‌ی محاسبه‌شده از بازه‌ها مرجع است |
| `leadership_unsupported` | مهارت نرم ↔ سوابق | «رهبری» بدون عنوان سرپرستی/مدیریتی و با سابقه‌ی کمتر از ۳ سال ← امتیاز نصف |
| `agent_failed` | هر عامل | شکست یا تمام شدن زمان ← بخش `failed`، وضعیت کل `partial` |

هر تعارض با عامل‌های درگیر، توضیح و راه‌حل در `conflicts_resolved` ثبت می‌شود تا HR بداند چرا عددی تغییر کرده است.

## ۴. نمره‌ی نهایی

```
نمره = موتور نمره‌دهی قبلی (همان شش مؤلفه و وزن‌ها، روی داده‌ی یکپارچه)
       + پاداش مهارت نرم   = ۵ × میانگین سه امتیاز برتر × max(۰٫۵، اطمینان عامل)        (۰ تا +۵)
       − جریمه‌ی اعتبارسنجی = Σ (high ۶، medium ۳، low ۱)، حداکثر ۱۵                     (۰ تا −۱۵)
       ← محدود به ۰ تا ۱۰۰؛ applications.score_ai = گردشده‌ی آن
```

`matching` در خروجی، پایه، هر مؤلفه، پاداش و جریمه را جدا نشان می‌دهد.

## ۵. خروجی و ذخیره

- **`resumes.agent_analysis`:** JSON یکپارچه، رمزشده با Fernet، چون نام شرکت‌ها و سوابق را دارد. مایگریشن `c4f1a8e2b7d9` فقط یک ستون nullable اضافه می‌کند. رزومه‌های قبلی خالی می‌مانند.
- **سازگاری:** `skill_analysis` و `score_ai` با همان شکل قبلی نوشته می‌شوند. جستجوی مهارت/سابقه، ایندکس‌ها، آمار و بورد کانبان تغییری نمی‌بینند.
- **API:** HR خروجی را در `GET /api/v1/resumes/{id}` (فیلد جدید `agent_analysis`) می‌بیند؛ RBAC و RLS همان قبلی‌اند.
- **بازگشت فوری:** `RESUME_PIPELINE=linear` همان خط لوله‌ی ترتیبی قبلی را اجرا می‌کند، بدون تغییر کد یا صف.

## ۶. زمان پردازش (معیار پذیرش)

`loadtest/agent_benchmark.py` هر دو مسیر را روی همان فایل خام اجرا می‌کند: استخراج متن، پارس، تحلیل و نمره. هر دو داخل `asyncio.run` اجرا می‌شوند، مثل Worker. ترتیب اجرا در هر دور جابه‌جا می‌شود.

**مجموعه‌ی آزمون:** ۲۴ رزومه، شامل ۸ PDF اسکن‌شده (OCR)، ۸ PDF متنی، ۴ DOCX انگلیسی و ۴ DOCX فارسی؛ ۳ دور.

**محیط:** ایمیج بک‌اند (Linux، Python 3.11، همان Tesseract و مدل NER) با **۲ هسته‌ی CPU** (`docker run --cpus=2`)، مثل سرور.

| نوع | خطی median / p95 | چندعاملی median / p95 | نسبت median / p95 |
|---|---|---|---|
| PDF اسکن‌شده | 1697.2 / 2119.7 ms | 1726.0 / 2237.8 ms | 1.017 / 1.056 |
| PDF متنی | 33.5 / 50.9 ms | 37.8 / 51.0 ms | 1.128 / 1.003 |
| DOCX انگلیسی | 41.9 / 47.0 ms | 46.6 / 54.4 ms | 1.110 / 1.157 |
| DOCX فارسی | 35.6 / 50.2 ms | 38.1 / 47.1 ms | 1.070 / 0.940 |
| **کل ترکیب** | 42.7 / 2102.2 ms | 45.6 / 2206.9 ms | **1.067 / 1.050** ✅ (سقف ۱٫۱۰) |

- **فاز سه عامل:** median ۱٫۶ ms و p95 ۲٫۳ ms. هم‌پوشانی سه عامل در ۷۲ اجرا از ۷۲.
- **دو دور بهینه‌سازی:** نسبت اولیه ۱٫۵۱ بود. این‌ها آن را پایین آوردند:
  - Thread Pool ماندگار
  - اجرای مستقیم توزیع
  - حذف تبدیل رفت‌وبرگشتی Pydantic
  - محاسبه‌ی یک‌باره‌ی سیگنال‌های مشترک
  - یک پیمایش متن برای مهارت‌ها
  - الگوی ترکیبی واژه‌نامه
- **روی خود سرور:** `bash deploy/agents-check.sh` همین benchmark را روی CPU خود سرور اجرا می‌کند.
- **سربار:** روی رزومه‌های متنی کوچک، سربار ثابت حدود ۳ تا ۴ میلی‌ثانیه است، چون تحلیل‌های جدید (مهارت نرم، بزرگ‌نمایی، حل تعارض) کار اضافه‌ی واقعی‌اند. روی رزومه‌های اسکن‌شده (OCR) این سربار ناچیز است.

## ۸. محدودیت‌ها

- **عامل‌ها قاعده‌محورند** (گراف مهارت، قواعد تاریخ، واژه‌نامه)، نه مدل زبانی. Production مدل زبانی ندارد و این باعث سریع، قطعی و بدون هزینه بودن آن‌ها است. گراف و واژه‌نامه کامل نیستند (مهارت یا عبارت خارج از فهرست شناخته نمی‌شود) و با افزودن داده گسترش می‌یابند.
- **تحلیل لحن ساده است:** بر پایه‌ی نشانه‌های واژگانی است، نه فهم معنایی. «تناسب فرهنگی» پیشنهادی است، و برای تصمیم استخدامی به‌تنهایی کافی نیست.
- **Thread عاملی که زمانش تمام شده** تا پایان کارش ادامه می‌دهد (Thread قابل کشتن نیست). ظرفیت Pool بیش از سه عامل در نظر گرفته شده است.
- **رزومه‌های قبلی** `agent_analysis` ندارند تا وقتی دوباره پردازش شوند.
- **ورودی صف** هنوز آدرس فایل را دارد (همان قرارداد قبلی). آدرس از لاگ‌ها حذف شده است.
